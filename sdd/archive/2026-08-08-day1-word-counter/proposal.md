## 為什麼做

2026 iThome 鐵人賽 Vibe Coding 系列 Day1，選定 100 題清單第 9 題「字數與段落統計器」：稿件、投稿、公告常有字數上限，但 Word／Google Docs 對中英文混排、標點符號的計算方式不直覺，使用者常常送出後才發現超字數被退件，需要一個「貼上文字立即看到明確、可信賴數字」的小工具。

## 要改什麼

依 `PRD.md` 定案的 A 類交付（GitHub Pages／下載 HTML，純前端、零外部依賴、離線可用）：

1. 建立 `Day1/index.html`：中英文混排字數統計核心邏輯、即時統計、自訂字數上限與超標警示、匯出 Markdown/CSV 報告。
2. 版面決策：判斷本工具是單頁小工具（textarea + 統計卡片 + 幾顆按鈕），不另開獨立 UI 設計文件，改在本提案內以 ASCII wireframe 定案桌面版與手機版版面。

```
桌面版（≥768px）                      手機版（375px）
┌─────────────┬─────────────┐        ┌─────────────────┐
│             │  統計卡片    │        │   統計卡片        │
│  文字輸入區  │  中文/英文/  │        │  (堆疊顯示)       │
│  (textarea) │  總字數/段落 │        ├─────────────────┤
│             │  上限進度條  │        │   文字輸入區      │
│             ├─────────────┤        │   (textarea)     │
│             │ 清空/複製/   │        ├─────────────────┤
│             │ 匯出MD/CSV  │        │ 清空/複製/匯出按鈕 │
└─────────────┴─────────────┘        └─────────────────┘
```

3. 驗證方式：不接受「應該沒問題」的自我推論，改用 Playwright `browser_evaluate` 對 DOM 灌入人工核算過的中英文混排文字，逐項比對統計結果；`file://` 協定被 Playwright MCP 擋掉，改用 `python3 -m http.server` 做完整自動化測試，再用系統 `open` 指令以 `file://` 雙擊實測「不依賴伺服器」這條驗收條件。
4. 完成後執行 `SECURITY_REVIEW.md` 資安源碼檢測（XSS、注入、資料外洩等 OWASP 常見類別）。
