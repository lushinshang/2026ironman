# Tasks：PDF 密碼管理器（pdf-password-manager）

> 前置條件：`sdd/pdf-infra/` 已完成並驗收（`pdf-build.js` 的 `encryptPdf()`／
> `decryptPdf()` 已用真實 PDF 樣本驗證過加解密機制可行）。本檔**不包含**寫加解密
> 演算法本身的任務，只組裝 UI 與批次流程，見 `VibeCoding/shared/PDF_CONTRACT.md`。
> 待裁示 1–3 已定案，見 `sdd/LEVEL1D_RULINGS.md` 第 10–12 條：批次失敗不中止（T2）、
> 加密演算法不曝露給使用者選（本檔全程未做此 UI，與裁示一致）、PDF 權限功能不做
> （本檔全程未做此 UI，與裁示一致）。以下任務已依定案結果撰寫，不是暫定骨架。

- [x] T1 建立 `Day23_pdf-password-manager/src/index.html` 版面骨架：多檔上傳區
  （`setupDropZone()`／`setupFilePicker()`，`opts.multiple: true`，`gate` 接
  `checkPdfBatchSize()`）、模式選擇（解鎖／設定新密碼／更換密碼，三選一）、密碼輸入
  欄位（含明碼/遮罩切換）、批次結果列表（檔名／狀態／原因）、下載方式（單檔／ZIP）、
  共通三按鈕；套用 `shared/base.css`。
  **驗收**：情境：一次選取 3 份 PDF，畫面列出 3 個項目；情境：切換三種模式時，
  對應的密碼輸入欄位（1 組或 2 組）正確顯示/隱藏。

- [x] T2 實作「解鎖」模式：對批次每個檔案呼叫 `decryptPdf(bytes, password)`，成功者
  轉成未加密的 PDF bytes 存入結果，失敗者記錄失敗原因（密碼錯誤／檔案格式不支援）。
  依待裁示 1 的暫定方向：單一檔案失敗不中止批次，其餘檔案繼續處理。
  **驗收**：情境：對一份已知密碼的加密 PDF 輸入正確密碼，該項目標示成功並可下載
  未加密副本，用系統 PDF 檢視器開啟不再要求密碼；情境：對同一份 PDF 輸入錯誤密碼，
  該項目標示失敗且訊息可辨識為「密碼錯誤」；情境：批次中 1 份密碼正確、1 份密碼
  錯誤，正確的那份仍成功產出，錯誤的那份標示失敗，兩者互不影響。

- [x] T3 實作「設定新密碼」模式：對批次每個未加密 PDF 呼叫
  `encryptPdf(pdfDoc, {userPassword: 新密碼})`。
  **驗收**：情境：對一份未加密 PDF 設定新密碼，輸出檔用系統 PDF 檢視器開啟時要求
  輸入密碼，且該密碼與使用者輸入的一致；情境：對一份本來就已加密的 PDF 誤用此模式，
  UI 明確提示「此檔案已加密，請改用『解鎖』或『更換密碼』」，不產生誤導性結果。

- [x] T4 實作「更換密碼」模式：先用舊密碼呼叫 `decryptPdf()`，成功後再用新密碼呼叫
  `encryptPdf()`，兩步驟串接，中途任一步失敗即該檔案標示失敗並記錄是哪一步失敗。
  **驗收**：情境：輸入正確的舊密碼與一組新密碼，輸出檔用舊密碼無法開啟、用新密碼
  可以開啟；情境：舊密碼輸入錯誤，該檔案在「解密」步驟就標示失敗，不會產生「用
  錯誤舊密碼＋新密碼組出的half-way 檔案」這種混淆狀態。

- [x] T5 批次結果彙總與輸出：統計成功／失敗數量顯示於頁面頂端；提供逐檔下載按鈕；
  提供「下載全部成功項目 ZIP」按鈕（呼叫 `createZipBlob()`），失敗的檔案不進入 ZIP。
  **驗收**：情境：批次 5 份檔案中 3 成功 2 失敗，頁面顯示「3 成功／2 失敗」；情境：
  下載 ZIP 後解壓，內含 3 個成功檔案，不含失敗的 2 個；情境：全程檢查使用者上傳的
  原始 `File` 物件未被寫入或修改（原始檔案永遠不被覆寫）。

- [x] T6 密碼欄位安全與 UX 細節：密碼輸入不寫入 `localStorage`／`sessionStorage`／
  任何持久化儲存；明碼/遮罩切換按鈕；離開頁面或按「清除」時密碼欄位歸零。
  **驗收**：情境：輸入密碼後檢查瀏覽器 `localStorage`／`sessionStorage`，不存在任何
  含密碼明文的鍵值；情境：點擊明碼/遮罩切換按鈕，輸入欄位的 `type` 在 `text`／
  `password` 間正確切換。

- [x] T7 Level 1 共通 UI 基線與整合驗收：複製結果摘要文字（`io-clipboard.js`，摘要
  內容為成功/失敗統計，**不含任何密碼明文**）；`buildCleanHtmlCopy()` 清空已上傳
  佇列、密碼欄位、處理結果、`#__shared_toast`，移除 `.nav-back` 與站內連結；建立
  `src/bundle.json` 並跑 `scripts/bundle.py` 產出 `index.html`／`bundle_manifest.json`。
  **驗收**：情境：完整操作一輪（上傳→設密碼→下載→清除）後點擊「下載本工具離線版」，
  `file://` 開啟下載到的 `index.html`，重新走一次完整流程結果一致；情境：離線版載入後
  `document.getElementById('__shared_toast') === null`、
  `document.querySelectorAll('.nav-back').length === 0`，載入時 `pageerror` 與 console
  error 皆為空（Playwright 斷言，非原始碼 grep）；情境：複製摘要文字內容用
  Playwright 攔截剪貼簿內容，確認不含任何測試用密碼字串。

## 驗收條件（總結，抄 PRD 22 三條 + 補充）

- 情境：正確密碼可解鎖支援格式的 PDF（PRD 22 原文）。
- 情境：錯誤密碼不能產生假成功結果（PRD 22 原文）。
- 情境：重新加密後，開啟輸出檔需要新密碼（PRD 22 原文）。
- 情境：批次處理中任一檔案失敗不影響其餘檔案的正常產出（補充，對應待裁示 1 暫定
  方向的具體驗證）。
- 情境：全程密碼明文不出現在任何持久化儲存或複製到剪貼簿的摘要文字中（補充，
  對應本題引入密碼輸入後的新增資安風險面）。
