## PRD A1 — 贅詞與 AI 味檢查器

> 補記：v2 需求基線（`2026-ironman-vibecoding-30-prd.md`）30 題清單漏收此題（v1 Day2 原題），本檔案為補寫的 PRD，格式對齊基線內 PRD 03、PRD 04。編號採 `PRD A1`（A 代表 Additional／附加，明確不佔用基線 01-30 既有序號），與另一補回題 `PRD A2`（`text-diff`）並列，不代表兩者在基線中的相對位置。

- **英文短名稱**：`filler-word-checker`
- **類型**：新功能（v1 補回，原 v1 Day2）
- **部署型態**：單一 HTML / GitHub Pages，可離線
- **AI**：否
- **SDD**：`sdd/filler-word-checker/`

### 為什麼做

寫作者（尤其用 AI 協作寫初稿的人）定稿前常常沒清掉「基本上」「其實」這類贅詞，也沒發現「不僅如此」「值得一提的是」「賦能」「打造」這類 AI 生成文字常見的過渡語與抽象動詞高頻重複。這些詞單獨看沒問題，只有整篇統計上高頻出現才刺眼，人工逐句抓很花時間。

### 輸入

貼上文字，或拖曳單一 .txt / .md 檔案。

### MVP

- 可編輯主詞庫（詞彙＋分類：贅詞／AI 慣用語／抽象名詞），對輸入文字做精確字串比對，命中處依分類標色，且可勾選刪除。
- 標記結果可逐項勾選／取消（預設全選），按「執行刪除」才真正從文字中移除已勾選項目；未勾選維持原樣。
- 可編輯高頻監測詞庫，統計全文出現次數，達使用者可調門檻（預設 3 次）才標紅提醒；僅提示、不提供一鍵刪除。
  - **同一詞彙同時收錄於主詞庫與高頻監測詞庫時**：兩套判斷各自獨立套用、不互斥、無優先順序之分。分類色與是否可勾選刪除，一律只由「主詞庫身份」決定；高頻監測身份只疊加「達門檻標紅」的額外視覺提示（例如底線或外框疊加在分類色塊上，不覆蓋分類色），不會因為同時是高頻警示詞就變成不可刪除，也不會因為屬於主詞庫就不納入高頻計數。換句話說：「能不能刪」看主詞庫，「要不要標紅提示」看高頻監測，兩者同時生效。
- 段落開頭同構偵測：依空行切段，取每段開頭前 N 字（預設 5 字，可調）比對重複，重複 ≥ 2 段才標記；僅提示。
- 引號排除範圍：「」（直角引號）、『』（雙直角引號）、""（直式引號）、“ ”（彎引號／curly quotes）共四組成對符號，符號內的文字不列入上述三種偵測範圍。未閉合的引號（只出現開頭符號、掃描到文字結尾都找不到對應結尾符號）視為不成對，不排除其後文字——即該開頭符號之後的文字仍照常參與偵測。
- **「執行刪除」的修改對象是輸入區當下顯示的工作文字本身**（textarea 內容直接被改寫成刪除後的結果），不是另外維護一份唯讀原始副本。這不違反共通規則第 5 條「原始檔預設不得覆寫」——第 5 條指的是使用者拖曳進來的原始檔案本體不會被程式寫回硬碟；輸入區內的文字是使用者主動貼上／匯入待處理的工作內容，本來就會被本工具的偵測與刪除操作直接修改，「下載處理後 .txt」是另外產生新檔，不覆寫原始檔案。
- 主詞庫與高頻監測詞庫皆可匯出成 JSON、匯入還原；匯入格式錯誤需有明確提示、不中斷整頁。
- 統計摘要（各分類命中筆數、高頻詞警示組數、段落開頭重複組數、已刪除筆數）。
- 複製處理後文字、下載處理後 .txt。

### 詞庫 JSON 格式（schema）

主詞庫與高頻監測詞庫**皆為 JSON 陣列**，每筆元素為物件：

```json
// 主詞庫
[{ "word": "基本上", "type": "贅詞" }]
// type 僅限三選一："贅詞" | "AI 慣用語" | "抽象名詞"

// 高頻監測詞庫
[{ "word": "不僅如此" }]
```

**此格式與 Day04 `zh-tw-localizer` 的自訂詞庫格式不通用**：Day04 詞庫是**物件（鍵值對，`{"原詞": "替換詞"}`）**，且明確把「JSON 陣列」列為錯誤格式；本題詞庫是**陣列**。兩者用途不同（本題是分類標記詞庫，Day04 是一對一替換對照表），使用者不應預期兩題的匯出檔可以互相匯入。

### 不做

冗長句型自動改寫、排比／強調句型的語法對稱性判斷、AI 味濃度百分比評分、多檔案批次處理、詞庫的模糊比對或語意判斷。

### 驗收條件

- 情境：貼上含三種分類詞庫各一筆的文字並執行偵測，就會看到三種類型皆被標示且顏色不同。
- 情境：取消勾選其中一筆標記後執行刪除，就會看到該筆維持原樣、其餘勾選項目被正確刪除。
- 情境：高頻詞在全文出現次數未達門檻，就不會被標紅；達到門檻才標紅且不可勾選刪除。
- 情境：兩段以上開頭前 N 字相同的文字執行偵測，就會標記段落開頭重複；只有一段時不標記。
- 情境：引號（含「」『』""與彎引號 “ ”）內含詞庫詞彙的文字執行偵測，就會看到引號內文字不被標記。
- 情境：文字含未閉合的引號（只有開頭符號、無對應結尾），執行偵測時該開頭符號之後的文字仍正常參與偵測，不會整段被誤判為引號內容。
- 情境：同一詞彙同時存在於主詞庫與高頻監測詞庫，執行偵測後該詞依主詞庫分類標色且可勾選刪除，若全文出現次數達門檻，同時疊加標紅提示；勾選刪除該詞仍會成功移除，不因屬於高頻警示詞而被鎖定。
- 情境：新增自訂詞彙並執行偵測，就會看到該詞被正確標示；匯出詞庫 JSON 後清空再匯入，就會完整還原。匯出的 JSON 為陣列格式，每筆含詞彙與（主詞庫）分類欄位。
- 情境：拖曳 .txt/.md 檔案到輸入區，就會正確讀取內容並帶入。
- 情境：點擊「執行刪除」後，輸入區內的文字本身被改寫為刪除後結果（非另開唯讀副本），下載處理後 .txt 產生的是新檔，不覆寫使用者原始拖曳進來的檔案。
