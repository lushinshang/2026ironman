- [x] 9. `VibeCoding/index.html` 首頁與 `Day3/index.html` 互相連結，雙向都要用瀏覽器實際點擊測試；同步完成 `SECURITY_REVIEW.md` 資安檢測，須含源碼檢測（比照 Day1／Day2 方法論，不只是跑一次 Network 面板）：
  - 我方邏輯（app 層）：整份 `index.html` 自寫程式碼逐行讀一次，比對 OWASP 常見類別——有無 `innerHTML`／`insertAdjacentHTML`／`document.write`（XSS）、有無 `eval`／`Function()`（code injection）、有無 `fetch`／`XMLHttpRequest`（資料外洩）、下載檔名是否處理路徑穿越字元
  - 內嵌第三方函式庫（vendor 層）：對 jsdiff 的 `dist/diff.js` 做關鍵字掃描（`fetch`／`XMLHttpRequest`／`eval`／`new Function`），找出所有網路能力與動態執行程式碼位置，逐一確認我方呼叫方式是否會觸發，不能只看有沒有出現這些字串就下結論
  - 實測驗證：實際瀏覽器操作跑一輪比對流程，搭配監看 Network 面板確認零對外請求，產出格式比照 `Day2/SECURITY_REVIEW.md`

## 驗收條件

1. 情境：當貼上兩份句子數相同、但有 3 處修改的文字並執行比對，就會正確標出這 3 處修改，其餘句子標示為未變動。
2. 情境：當新版比舊版多出一整段文字並執行比對，就會把多出的句子標示為「新增」，不誤判為修改。
3. 情境：當新版比舊版少一段文字並執行比對，就會把缺少的句子標示為「刪除」，不誤判為修改。
4. 情境：當拖曳一個 .txt 檔案到左欄或右欄，就會自動讀取檔案內容並填入對應欄位。
5. 情境：當比對結果出現連續 3 句以上未變動，就會預設摺疊成一行「未變動 N 句」，點擊後可展開查看內容。
6. 情境：當點擊「下載差異報告 MD」，就會下載一個檔案，內容與畫面顯示的差異結果一致。
7. 情境：當用瀏覽器開發者工具監看 Network 面板跑完整個比對流程，就不會出現任何對外請求。
8. 情境：當直接以 `file://` 方式雙擊開啟 `index.html`，貼上文字並執行比對，就會正常運作、不出現錯誤。
9. 情境：當從 `VibeCoding` 首頁點擊 Day3 題目連結、或在 Day3 頁面點擊返回首頁連結，就都能正確跳轉到對應頁面。
