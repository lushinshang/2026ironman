## 驗收條件

- 情境：上傳一份含四個不同單位值的 CSV，選定該欄位為拆分欄位後，就 Unique Values 清單列出四組且各自可下載成四份獨立 CSV，內容為對應群組的資料列。（PRD 12 驗收條件 1）
- 情境：拆分依據欄位的群組值含 Windows 非法檔名字元（如 `/`、`:`）時，就自動產生的檔名已置換非法字元，且兩個置換後撞名的群組各自產出不互相覆蓋的檔案（`proposal.md` 撞名處理）。（PRD 12 驗收條件 2）
- 情境：拆分依據欄位的群組值恰好是 Windows 保留裝置名稱（如 `CON`、`nul`）時，就輸出檔名已附加 `_group` 後綴而非直接使用原始保留字。（PRD 12 驗收條件 2）
- 情境：未取消勾選任何群組時，就「原表總筆數」與「目前已選組別合計筆數」相等，UI 明確標示一致；取消勾選任一群組後兩者不再相等且 UI 明確標示已排除的組數與筆數。（PRD 12 驗收條件 3）
- 情境：使用者勾選排除某欄位後，就所有輸出檔案（單檔與 ZIP 內）的 header 與資料列都同步移除該欄位，其餘欄位順序不變。
- 情境：群組值為空字串時，就該群組仍被列出、可下載，檔名為 `(空值).csv`，不出現空白檔名或錯誤。
- 情境：使用含中文群組值的樣本產生 ZIP 後，用 macOS 原生工具實際解壓，就檔名顯示為正確中文字元，不是亂碼或問號。
- 情境：點擊「全部下載 ZIP」時，就只有目前勾選的群組被打包進 zip，未勾選群組不在 zip 內、但仍可透過「下載此份」單獨取得。
- 情境：下載的 `index.html`（`scripts/bundle.py` 產物）在斷網環境下以瀏覽器開啟，就能依序完成上傳 CSV、選定拆分欄位看到 Unique Values 清單、點擊任一群組的單檔下載取得內容正確的 CSV、點擊全部下載 ZIP 取得內容正確的 zip、點擊複製拆分摘要使剪貼簿內容含各群組名稱與筆數、點擊下載本工具離線版取得檔案，六個動作全部成功且瀏覽器 Console 無錯誤。
- 情境：上傳一份大小介於 5MB 與 20MB 之間的 CSV 時，就畫面顯示「檔案較大，處理可能需要數秒」提示後仍完成解析與分組；上傳一份大小超過 20MB 的 CSV 時，就畫面明確顯示已拒絕並說明上限，不觸發解析、不使頁面卡死。（`CSV_CONTRACT.md` 第 5 節）
- 情境：分別用拖放與檔案選取 input 上傳同一份超過 20MB 的 CSV，兩條路徑都被閘門擋住、都顯示拒絕訊息且都不進入解析——**檔案選取與拖放走同一條路**，不會有一條路徑繞過大小限制。
- 情境（`buildCleanHtmlCopy()` 離線版，`CONTRACT.md` 第 6 節硬性要求）：測試 CSV 的拆分欄位群組值與欄名一律改用哨兵值——群組值 `ZZSPLITVAL`、欄名 `ZZSPLITCOL`。使用者上傳含這兩個哨兵的 CSV 並完整操作一輪拆檔（含觸發一次 toast）後點擊「下載本工具離線版」，分兩種判定方式，**不可混用**：
  **(甲) 原始碼精確搜尋，各須 0 筆**（這兩個字串不可能出現在工具程式／CSS／文案裡）：`ZZSPLITVAL`、`ZZSPLITCOL`。
  **(乙) DOM 層判定**（用 Playwright 載入下載到的離線版產物後斷言，⚠️ 不可用 `grep` 判定）：`document.getElementById('__shared_toast') === null`、`document.querySelectorAll('.nav-back').length === 0`、`pageerror` 與 console error 皆為空。內嵌的 `base.css` 與 `ui-toast.js` 本來就含 `.nav-back`／`__shared_toast` 這兩個字串會被 `bundle.py` 內嵌進產物，grep 為 0 筆字面上不可能成立，見 `CONTRACT.md` 第 6 節。
