# 任務：Day4 個資與機敏資料遮蔽工具

- [x] 1. 建立 `Day4/index.html` 骨架：文字輸入區（textarea），支援拖曳單一 .txt/.md 檔案自動帶入內容（沿用 Day2／Day3 已驗證的拖曳邏輯）
- [x] 2. 實作個資偵測函式：4 種 regex（身分證字號、手機號碼、市話含分機、Email），用真實格式樣本（含邊界案例：分機、有無括號區碼、大小寫身分證開頭字母）覆核每種 regex 的準確度
- [x] 3. 機敏詞庫輸入區（textarea，每行一個關鍵字）＋精確字串比對函式（非 regex，避免使用者輸入的關鍵字含特殊字元造成非預期行為）
- [x] 4. 偵測結果渲染：原文字內以不同底色標示個資／機敏詞彙（附色彩圖例），每處標示旁附勾選框（預設全部勾選）
- [x] 5. 「執行遮蔽」邏輯：只替換已勾選項目為 `[已遮蔽]`，未勾選項目維持原樣；同步更新統計摘要（個資／機敏詞彙／已遮蔽筆數）
- [x] 6. 「複製遮蔽後文字」與「下載遮蔽後 .txt」按鈕，下載內容需與畫面顯示一致
- [x] 7. `VibeCoding/index.html` 首頁與 `Day4/index.html` 互相連結，雙向都要用瀏覽器實際點擊測試；同步完成 `SECURITY_REVIEW.md`（比照 Day1～Day3 方法論），須含源碼檢測：
  - 我方邏輯逐行讀一次，比對 OWASP 常見類別——有無 `innerHTML`／`insertAdjacentHTML`／`document.write`（XSS，本工具會把使用者輸入的文字重新渲染進畫面，風險點需特別檢查）、有無 `eval`／`Function()`、有無 `fetch`／`XMLHttpRequest`（本工具處理的資料是個資，零對外連線是核心承諾，需比 Day1～Day3 更嚴格驗證）
  - 實測驗證：實際瀏覽器操作跑一輪偵測＋遮蔽流程，搭配監看 Network 面板確認零對外請求
- [x] 8. 更新 `Day4/README.md` 開發日誌與進度勾選、`VibeCoding/readme.md` 進度看板

## 驗收條件

1. 情境：當貼上含身分證字號、手機號碼、市話（含分機）、Email 各一筆的文字並執行偵測，就會四種格式皆被正確標示。
2. 情境：當貼上一份自訂機敏詞庫（例如「XYZ-001」）與含該詞彙 2 次的文字並執行偵測，就會兩處皆被標示。
3. 情境：當在標示結果中取消勾選其中一筆並執行遮蔽，就會該筆內容維持原樣不被替換、其餘勾選項目正確替換為 `[已遮蔽]`。
4. 情境：當拖曳一個 .txt 檔案到輸入區，就會自動讀取檔案內容並帶入。
5. 情境：當點擊「下載遮蔽後 .txt」，就會下載一個檔案，內容與畫面顯示的遮蔽後文字一致。
6. 情境：當用瀏覽器開發者工具監看 Network 面板跑完整個偵測＋遮蔽流程，就不會出現任何對外請求。
7. 情境：當直接以 `file://` 方式雙擊開啟 `index.html`，貼上文字並執行偵測與遮蔽，就會正常運作、不出現錯誤。
8. 情境：當貼上一段完全不含個資、也不含機敏詞庫任何關鍵字的文字並執行偵測，就會統計摘要顯示 0 筆，不誤判。
9. 情境：當從 `VibeCoding` 首頁點擊 Day4 題目連結、或在 Day4 頁面點擊返回首頁連結，就都能正確跳轉到對應頁面。
