# PDF 頁碼 / 浮水印 / 送審章（pdf-review-stamper）

- PRD 對應：`VibeCoding/2026-ironman-vibecoding-30-prd.md` `## PRD 20`
- 部署型態：單一 HTML / GitHub Pages，可離線
- AI：否
- SDD：`sdd/pdf-review-stamper/`
- 產品目錄：`VibeCoding/Day22_pdf-review-stamper/`
- 資料層依據：`VibeCoding/shared/PDF_CONTRACT.md`（全文，特別是第 1.3 節與第 4 節
  `pdf-build.js`）。`addPageNumbers()`／`addWatermarkText()`／`embedCjkFont()` 由
  `sdd/pdf-infra/` 前置工程建立，本提案假設其機制已就緒，**不重新設計加解密／頁面
  結構編輯的底層邏輯**，只處理本題特有的「中文字型要用哪一份」與「浮水印互動細節」。

## 為什麼做

草稿、密件、僅供參考、未核定等標記與頁碼，是送審文件高度重複的加工。PRD 20 的 MVP
本身不複雜（畫頁碼、畫浮水印文字、控制透明度／角度／位置／頁碼範圍），但契約第 1.3
節已經點名這是本 Level 技術難度最高的一題——**不是因為邏輯難，是因為中文字型嵌入這件事
本身就有無法迴避的取捨**，見下方「待裁示」。

## 本題與 `pdf-infra` 的分工

- `pdf-infra` 提供：`addPageNumbers()`（頁碼，只需要數字與 `/`，`StandardFonts` 即可
  處理，不需要中文字型）、`addWatermarkText()`（浮水印繪製機制）、`embedCjkFont()`
  （`registerFontkit` + `embedFont` 的機制本身，已用測試字型驗證過可行）。
- 本題負責：選定實際要嵌入的中文字型檔（待裁示，見下方）、浮水印預覽 UI、透明度／
  角度／位置的互動控制、頁碼範圍套用邏輯的畫面呈現。

## 要改什麼

- 建立 `VibeCoding/Day22_pdf-review-stamper/src/index.html`：上傳區（接
  `checkPdfFileSize()` gate）、PDF 頁面預覽（接 `renderPageToCanvas()`）、頁碼設定區
  （位置：頁首／頁尾；格式：`X` 或 `X/Y`）、浮水印設定區（4 個預設文字按鈕＋自訂文字
  輸入框、透明度滑桿、角度滑桿、位置選項）、頁碼範圍選擇（全頁／指定範圍）、預覽區、
  輸出按鈕。
- 中文字型嵌入：依裁示結果，在初次需要畫中文文字時呼叫一次 `embedCjkFont()`，之後
  複用同一個 `PDFFont` 物件（不必每次繪製都重新嵌入）。

## 待裁示

### 1.（最重要）中文字型嵌入方案——**必須裁示，本提案不自行決定**

契約第 1.3 節已定調：`pdf-lib`／`@cantoo/pdf-lib` 不內建中文字形，PRD 要求的四個
預設浮水印文字（草稿／密件／僅供參考／未核定）與使用者自訂浮水印文字都需要真實
中文字型檔嵌入。三個選項各自的取捨：

**方案 A：完整思源黑體 Noto Sans TC（或思源宋體），OFL 授權**
- 優點：字符覆蓋率完整，使用者可自訂任意中文浮水印文字（含罕見字），字型美觀度高
  （Google／Adobe 出品，公文常見字體風格）。
- 缺點：完整字型檔案通常數 MB 到十幾 MB（依字重與是否含全字庫），直接內嵌進單檔
  HTML 會讓 `Day22_pdf-review-stamper/index.html` 的下載體積遠超本系列目前任何一題
  （目前最大的 Level 1c 產品含圖片處理程式碼也只有數十 KB 到低百 KB 量級，字型檔案
  是完全不同量級的負擔）。

**方案 B：較小的開源中文字型或政府開源字型**
- 優點：檔案可能較小（依實際找到的字型而定，需要查證才知道具體數字，本提案不假設
  一定比方案 A 小很多——中文字型的檔案大小主要取決於字符集大小而非「品牌」）。
- 缺點：字符覆蓋率與美觀度的實際情況需要逐一查證候選字型才能知道，可能覆蓋率不足
  導致使用者輸入罕見字時出現缺字方框；本提案沒有現成候選清單，需要另外花時間調查。

**方案 C：限制浮水印文字範圍，用小型字型子集**
- 做法：浮水印只能從 4 個固定預設（草稿／密件／僅供參考／未核定）+ 英數字自訂文字
  中選，**不支援任意中文自訂文字**；字型檔只需子集化涵蓋這 4 組固定詞用到的中文字
  （約 10–15 個不重複字），子集化後的字型檔可以小到幾十 KB 量級。
- 優點：徹底避開「使用者可自訂任意文字」與「字型必須完整涵蓋所有可能字符」的根本
  衝突，檔案體積問題消失。
- 缺點：**犧牲 PRD 明列的「自訂文字浮水印」功能中的中文自訂能力**（英數字自訂文字
  仍可用 `StandardFonts`，不受影響）——這是對 PRD MVP 範圍的實質縮減，不是單純的
  實作細節選擇，需要指揮官明確同意這個取捨。

**方案 D：其他**——若指揮官有其他考量（例如已經知道某個字型授權或體積特別適合、
或願意接受更複雜的執行時子集化方案），本提案沒有預設立場。

**裁示：見 `sdd/LEVEL1D_RULINGS.md` 裁示 1，定案為方案 A**（使用者 2026-08-24，
「1.A」）——完整思源黑體 Noto Sans TC（OFL 授權），接受檔案體積代價（預估數 MB 到
十幾 MB），換取使用者可自訂任意中文浮水印文字。**這不再是暫定，方案 A 已是唯一
路徑**：`tasks.md` 的字型嵌入任務不應再寫「任一測試用字型」這種暫定用法，直接下載
Noto Sans TC（或其繁體中文子集版本，若官方有分版本）固定版本，依
`shared/vendor/README.md` 慣例記錄版本／授權／來源 URL／SHA-256。方案 B／C／D
不再需要評估。檔案體積是裁示當下已知且接受的取捨，實作完成後誠實記錄實際數字即可，
不需要因為體積大而回頭質疑裁示本身。

### 2. 浮水印透明度／角度／位置的預設值

PRD 20 只寫「透明度、角度、位置」三個可調參數，沒有給預設值與位置選項的具體清單。
暫定：透明度預設 50%、角度預設 45°（常見的對角線浮水印慣例）、位置提供「左上／
置中／對角線（貫穿整頁）」三個選項，對角線為預設。

### 3. 預覽是即時渲染還是靜態示意

PRD 20 驗收條件「使用者可先預覽再下載」沒有規定預覽的即時程度。兩個選項：
(a) 每次調整透明度／角度／位置滑桿都即時重新渲染当前頁的 canvas（體驗好，但若
    `addWatermarkText()` 走完整 `@cantoo/pdf-lib` 流程重新產生整份 PDF 再渲染，
    每次滑桿拖動都重跑一次可能造成明顯延遲，需要另外設計「輕量預覽」路徑，
    例如直接在既有渲染好的頁面 canvas 上疊加一層 CSS/canvas 繪製的浮水印文字近似
    效果，不走完整 `pdf-lib` 產生流程）；
(b) 調整參數後需要使用者按下「產生預覽」按鈕才重新渲染（實作簡單，但體驗上使用者
    無法看到即時反饋，可能要多次調整-按鈕-調整才能找到滿意的效果）。
**暫定選 (b)**（按鈕觸發式預覽），理由是實作複雜度明顯較低，且送審章這類文件通常
一次設定好套用到全部頁面，不像 Day17 的透視校正需要連續拖曳互動的即時回饋，兩題的
互動需求本質不同。

**裁示：見 `sdd/LEVEL1D_RULINGS.md` 第 9 條，採選項 (b) 定案**（指揮官代為決定，
2026-08-24，「剩下幫我決定」授權），不做即時渲染，不需要 Tier 1/2/3 式的分工。
