# Tasks — pdf-review-stamper（Day22）

> 前置條件：`sdd/pdf-infra/` 完成並驗收（`pdf-decode.js`／`pdf-build.js`／
> `pdf-file-size.js` 就緒）。本檔不包含「接 pdf.js」「接 pdf-lib」「寫字型嵌入機制」
> 之類的任務，直接引用契約簽名，見 `VibeCoding/shared/PDF_CONTRACT.md`。
>
> **裁示已定案，見 `sdd/LEVEL1D_RULINGS.md` 裁示 1／第 8 條／第 9 條**：中文字型用
> Noto Sans TC（方案 A）、浮水印透明度 50%／角度 45°／位置三選項對角線預設、預覽採
> 按鈕觸發式 (b)。以下任務直接依此定案撰寫，不再是暫定骨架。

- [x] 1. 建立 `Day22_pdf-review-stamper/src/index.html` 版面骨架與上傳流程：上傳區
  （接 `checkPdfFileSize()` gate，讀檔前先過大小閘門）、`loadPdfFile()` 讀入後顯示
  總頁數、頁面預覽區（`renderPageToCanvas()` 渲染目前選中頁）、上一頁／下一頁導覽；
  套用 `shared/base.css`。
  **驗收**：情境：上傳一份超過大小閘門上限的 PDF，畫面顯示拒絕訊息且不進入
  `loadPdfFile()`；情境：上傳一份正常的多頁 PDF，畫面正確顯示總頁數與第 1 頁預覽；
  情境：點擊上一頁／下一頁，預覽區切換到對應頁面且畫面內容與該頁實際內容相符。

- [x] 2. 實作頁碼功能：位置（頁首／頁尾）與格式（`X` 或 `X/Y`）設定，套用
  `addPageNumbers()`（僅需 `StandardFonts`，不涉及中文字型），支援全頁或指定頁碼範圍。
  **驗收**：情境：指定第 2–5 頁套用頁碼，其他頁不出現頁碼（對應 PRD 驗收條件）；
  情境：`X/Y` 格式的 `Y` 值等於輸出 PDF 的實際總頁數；情境：頁首與頁尾兩種位置各測
  一次，頁碼確實出現在對應位置（非文件內容區域重疊遮擋）。

- [x] 3. 複用 `sdd/pdf-infra/` 任務 1 已下載好的 Noto Sans TC vendor 資產（不重複
  下載），呼叫 `embedCjkFont()` 嵌入，字型物件複用（不重複嵌入）。
  **驗收**：情境：用 Noto Sans TC 繪製「草稿」二字到 PDF 頁面，輸出 PDF 用系統 PDF
  檢視器開啟能正確顯示「草稿」二字（非缺字方框、非亂碼）；情境：同一份已嵌入字型的
  `PDFDocument` 物件用於多次 `addWatermarkText()` 呼叫，不需要每次重新嵌入（效能與
  正確性都成立）。

- [x] 4. 實作浮水印四個預設文字按鈕（草稿／密件／僅供參考／未核定）與自訂文字輸入框，
  套用 `addWatermarkText()`，支援透明度、角度、位置三個可調參數（透明度預設 50%、
  角度預設 45°、位置「左上／置中／對角線」三選項，對角線為預設）。
  **驗收**：情境：點擊「草稿」預設按鈕，輸出 PDF 頁面出現半透明「草稿」浮水印文字，
  角度與位置符合設定值；情境：自訂文字輸入框輸入中文字串套用，輸出結果正確顯示
  （驗證任務 3 的字型嵌入在自訂文字情境下同樣生效，不是只有 4 個預設詞正確）；
  情境：透明度滑桿調整後輸出的浮水印視覺上确实變淡/變深（用像素取樣或肉眼比對
  記錄）。

- [x] 5. 實作套用範圍（全頁／指定頁碼範圍）套用到浮水印功能（頁碼功能已在任務 2
  處理範圍邏輯，本任務把同一套範圍邏輯套用到浮水印，兩者範圍設定各自獨立，使用者
  可以「頁碼套全頁、浮水印只套第 1 頁」這種組合）。
  **驗收**：情境：浮水印指定套用第 1 頁，其他頁不出現浮水印，但頁碼（若同時設定
  全頁）仍正常出現在全部頁面，證明兩套範圍邏輯互不干擾；情境：頁碼範圍與浮水印
  範圍分別設定不同區間，各自套用結果正確。

- [x] 6. 實作按鈕觸發式預覽（選項 (b) 定案，不做即時渲染）：使用者按下「產生預覽」
  才重新渲染，接「產生預覽」→「下載新 PDF」的流程。
  **驗收**：情境：設定好頁碼與浮水印參數後點擊「產生預覽」，預覽區顯示套用效果，
  且與最終下載的 PDF 視覺一致（不是預覽一套、實際輸出又是另一套結果）；情境：
  使用者可以在預覽階段調整參數後重新預覽，不需要重新上傳原始 PDF。

- [x] 7. 共通 UI 基線與整合驗收：複製結果（`shared/io-clipboard.js`，複製目前設定
  摘要文字，例如「頁碼：頁尾 X/Y，浮水印：草稿 50% 透明 45°，套用範圍：全頁」）；
  `buildCleanHtmlCopy()` 清空已上傳 PDF、頁碼與浮水印設定、預覽狀態、
  `#__shared_toast` 元素，移除 `.nav-back` 與站內連結；建立 `src/bundle.json` 並跑
  `scripts/bundle.py` 產出 `index.html`／`bundle_manifest.json`，**記錄字型檔內嵌後
  的最終 HTML 檔案大小**（對應 proposal.md 待裁示 1 提到的體積疑慮，用實測數字讓
  使用者判斷是否可接受，不是臆測）。
  **驗收**：情境：完整操作一輪（上傳→設定頁碼→設定浮水印→預覽→下載）後點擊
  「下載本工具離線版」，`file://` 開啟下載到的 `index.html`，重新走一次完整流程
  結果一致；情境：離線版載入後 `document.getElementById('__shared_toast') === null`、
  `document.querySelectorAll('.nav-back').length === 0`、載入時 `pageerror` 與
  console error 皆為空（Playwright 斷言）；情境：`bundle_manifest.json` 記錄的最終
  `index.html` 檔案大小已寫入回報，供使用者評估待裁示 1 的取捨是否需要重新考慮。

## 驗收條件（總結，抄 PRD 20 + 補充）

- 情境：指定第 2–5 頁時其他頁不加標記。
- 情境：`X/Y` 的 `Y` 為輸出總頁數。
- 情境：使用者可先預覽再下載。
- 情境：中文浮水印文字（預設詞與自訂文字）在輸出 PDF 中正確顯示，非缺字方框。
- 情境：原始上傳的 PDF 檔案不被覆寫或修改。
