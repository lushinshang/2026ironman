# Tasks：PDF 文字擷取與全文搜尋（pdf-text-search）

> 前置條件：`sdd/pdf-infra/` 完成並驗收（`pdf-decode.js`／`pdf-file-size.js` 就緒）。
> 本檔不包含「接 pdf.js」之類的任務，直接引用契約第 3 節簽名，見
> `VibeCoding/shared/PDF_CONTRACT.md`。片段長度／模糊匹配／多關鍵字邏輯／定位呈現方式
> 依 `proposal.md`「待裁示」1–4 項的裁示結果套用，本檔先建立流程骨架與驗收框架。

- [x] 1. 建立 `Day20_pdf-text-search/src/index.html` 版面骨架與上傳流程：上傳區（接
  `checkPdfFileSize()` gate + `loadPdfFile()`，讀檔前先過大小閘門，`reject` 時不進入
  `loadPdfFile()`）、逐頁文字顯示區、搜尋輸入框與結果列表、TXT/Markdown/Copy All
  匯出按鈕、三個共通按鈕（`CONTRACT.md` 第 6 節基線）；套用 `shared/base.css`。
  **驗收**：情境：上傳一份超過大小閘門上限的 PDF，畫面顯示拒絕訊息且不進入
  `loadPdfFile()`；情境：上傳一份正常的多頁文字層 PDF，畫面顯示逐頁文字內容，
  頁碼與該 PDF 實際頁數相符。

- [x] 2. 載入完成後呼叫 `extractAllText(pdfDoc)`，快取到 `state.pages`；實作文字層
  偵測邏輯：全部頁面 `text.trim()` 皆為空字串才判定為「無可擷取文字」並顯示限制提示，
  單一頁面為空不觸發整份文件的限制提示。
  **驗收**：情境：上傳一份純掃描影像 PDF（無文字層），畫面明確顯示「本文件無可擷取
  文字，可能是掃描檔」之類的限制提示，不嘗試 OCR、不顯示空白的逐頁文字區塊當作
  正常結果；情境：上傳一份文字層 PDF 但其中一頁是空白頁（例如封面背面），該頁
  逐頁顯示區標示「本頁無可擷取文字」，但整份文件不觸發限制提示（因為其他頁有文字）；
  情境：上傳一份文字層極少但確實存在的 PDF（例如只有頁碼與一行標題），不誤判為
  無文字層文件。

- [x] 3. 實作全文搜尋：輸入框接 `debounce()` 150ms，搜尋 `state.pages`，依裁示結果
  套用片段長度、大小寫/模糊匹配規則（`proposal.md` 待裁示 1、2），列出命中頁碼與片段。
  **驗收**：情境：輸入一個確實存在於文件中的關鍵字，結果列表顯示正確的頁碼與片段，
  片段內容包含該關鍵字；情境：輸入一個不存在的關鍵字，結果列表顯示「查無結果」
  而非空白或報錯；情境：清空輸入框，結果列表清空（不殘留上一次搜尋結果）；情境：
  依裁示的大小寫規則測試（例如裁示為大小寫不敏感時，用全大寫輸入去搜尋文件中的
  小寫關鍵字，仍能命中）。

- [x] 4. 實作點擊搜尋結果定位頁面：依裁示結果（`proposal.md` 待裁示 4）捲動／跳轉到
  對應的逐頁顯示區塊並提供視覺提示（例如高亮邊框）。
  **驗收**：情境：點擊某一則搜尋結果，畫面捲動到該頁對應的文字顯示區塊，且該區塊
  有明顯的視覺提示（不是使用者要自己找）；情境：連續點擊不同頁碼的搜尋結果，畫面
  正確跳到各自對應的頁面，不會卡在第一次點擊的位置。

- [x] 5. 實作匯出：TXT（全文字依頁碼分段標示）、Markdown（`## 第 N 頁` 分節）、
  Copy All（複製全文字，接 `io-clipboard.js`）。
  **驗收**：情境：點擊「下載 TXT」，下載內容依頁碼分段，內容與畫面顯示的逐頁文字
  一致（無截斷、無亂碼，含中文）；情境：點擊「下載 Markdown」，下載內容用
  `## 第 N 頁` 分節，可用 Markdown 檢視器正常渲染；情境：點擊「Copy All」，剪貼簿
  內容與 TXT 匯出內容一致（用 Playwright 攔截 clipboard 寫入內容比對，不用
  `fetch(blob:URL)`）。

- [x] 6. 共通 UI 基線與整合驗收：`buildCleanHtmlCopy()` 清空已上傳 PDF、擷取的文字
  快取、搜尋狀態、`#__shared_toast` 元素，移除 `.nav-back` 與站內連結；建立
  `src/bundle.json` 並跑 `scripts/bundle.py` 產出 `index.html`／`bundle_manifest.json`。
  **驗收**：情境：完整操作一輪（上傳→擷取→搜尋→定位→匯出）後點擊「下載本工具
  離線版」，`file://` 開啟下載到的 `index.html`，重新走一次完整流程結果一致；
  情境（比照 `csv-doctor` T10 慣例，測試文字改用可辨識的哨兵字串）：離線版載入後
  `document.getElementById('__shared_toast') === null`、
  `document.querySelectorAll('.nav-back').length === 0`、載入時 `pageerror` 與
  console error 皆為空（Playwright 斷言，非原始碼 grep）；情境：`scripts/bundle.py`
  執行後產出的 `index.html` 用 `file://` 與本機伺服器各測一次完整流程，上傳同一份
  測試 PDF 後搜尋結果一致。

## 驗收條件

- 情境：有文字層 PDF 可搜尋並列出頁碼（PRD 驗收條件 1）。
- 情境：掃描 PDF 無文字層時明確提示限制（PRD 驗收條件 2）。
- 情境：匯出文字與可擷取內容一致（PRD 驗收條件 3）。
- 情境：文字層偵測邏輯在邊界情況（單一空白頁、文字層極少）不誤判（見任務 2，
  本題提案階段主動補充的驗收條件，PRD 原文未涵蓋此邊界）。
