# Day 4 PRD — 文件去識別化工具

> 🔀 **本內容原編號 Day4，因系列重新分類移至現在的 Day9，後續將延伸為「可逆式去識別化工具」。**

> 交付類型：**A 類**（GitHub Pages／下載 HTML，純前端執行，零外部函式庫依賴）

---

## 1. 背景與痛點

### 主情境：接續 Day2／Day3 管線的外傳前檢查

承辦人員把 PDF 轉成文字（Day2）、跟舊版比對出差異（Day3）之後，差異報告或整理好的文字常常還沒清過個資與機敏內容，就要外傳或送簽。手動逐字檢查身分證字號、電話、Email 容易漏看；文件裡的專案代號、金額、承辦人姓名這類「機敏但沒有固定格式」的內容，更是只能靠人工肉眼抓，稍不注意就外流。

### 延伸情境

- 客服／民眾陳情紀錄要整段轉發給其他單位或做成教育訓練教材前，需先遮蔽陳情人聯絡方式。
- 報名表／履歷批次整理成名單時，姓名保留但身分證號、聯絡電話要先遮蔽才能給非核心承辦人查看。

## 2. 目標使用者

- 主要：一般辦公室行政人員、承辦人員，不具備程式背景
- 次要：需要在外傳文件前自我檢查個資與機敏內容的一般使用者

## 3. 使用情境（User Story）

1. 身為要外傳公文的承辦人員，我把文字貼進工具，系統標出疑似身分證字號、手機、市話、Email、姓名的位置（標色但不自動遮蔽），我逐一確認「這個要遮 / 這個不用」後才手動觸發遮蔽，遮蔽時依類型套用部分遮蔽規則（例如姓名顯示「王○○」、手機只留末 3 碼），避免自動誤判刪掉不該刪的內容、也避免整段消失導致文件難以閱讀。
2. 身為要外傳含專案代號或金額的文件的承辦人員，我在「機敏字庫」貼上一份自訂關鍵字清單（每行一個詞），如果這個詞有更適合的代換寫法（例如把專案代號代換成通用說法），就在「代換字庫」對應同一行填入代換詞；命中後直接套用，不需要再逐一勾選確認。
3. 身為接續 Day3 差異比對流程的承辦人員，我把差異報告的文字貼進本工具，遮蔽完個資、代換完機敏詞彙後才複製或下載，形成「轉文字 → 比對差異 → 遮蔽／代換 → 外傳」的完整流程。

## 4. 功能需求（MVP，本次必須完成）

| # | 功能 | 說明 |
|---|---|---|
| F1 | 文字輸入 | 單一文字輸入區，支援直接貼上，也支援拖曳單一 .txt/.md 檔案自動帶入內容（沿用 Day2／Day3 的拖曳邏輯） |
| F2 | 個資自動偵測（regex＋姓氏字典） | 偵測 5 種個資：身分證字號、手機號碼、市話（含區碼與分機）、Email（皆用 regex）、姓名（用內建常見中文姓氏字典比對「姓氏＋後續 1～2 個中文字」，屬啟發式判斷，見第 5 節已知限制）。偵測結果以底色標示，**不自動遮蔽** |
| F3 | 個資規則式部分遮蔽 | 使用者勾選確認後執行遮蔽，各類型套用對應規則（見第 8 節「個資遮蔽規則」），不是統一換成同一個固定符號 |
| F4 | 機敏字庫＋代換字庫（一對一行號對應） | 兩個獨立 textarea：「機敏字庫」每行一個關鍵字，「代換字庫」每行對應機敏字庫同一行的代換詞。工具對輸入文字做精確字串比對（非 regex）標出所有符合位置 |
| F5 | 機敏字庫命中後直接套用 | 機敏字庫（含代換字庫）命中後**不經過勾選確認**，直接執行代換：若代換字庫對應行有填代換詞，換成該代換詞；若代換字庫對應行是空的，退回預設效果、換成 `[已遮蔽]` |
| F6 | 個資人工確認機制 | F2 標出的每一處疑似個資皆可個別勾選或取消，使用者確認後點擊「執行遮蔽」才會依規則真正替換文字；機敏字庫／代換字庫維持 F5 的直接套用，兩種機制分開觸發 |
| F7 | 統計摘要 | 顯示「偵測到個資 N 筆／機敏字庫命中 N 筆／已遮蔽 N 筆／已代換 N 筆」 |
| F8 | 複製與下載 | 一鍵複製處理後文字；一鍵下載處理後的 .txt 檔案 |

## 5. 非必要／可延伸功能（Nice to have，非 Day4 範圍）

- 地址、生日、銀行帳號、信用卡卡號的自動偵測（格式變體太多，regex 誤判率高，先不做）
- 機敏字庫／代換字庫的模糊比對或語意判斷（AI/NLP 判斷「這段話是不是機密」）
- 批次多檔案處理
- PDF／圖片內文字的直接偵測（僅處理已轉出的純文字，需先用 Day2 工具轉檔）
- 姓名偵測的姓氏字典擴充維護、複姓／罕見姓氏支援（本次先用一份常見單姓清單）

> 上述功能明確排除於 Day4 MVP，避免範圍膨脹；若後續有需求再開新任務。

**已知限制（姓名偵測）**：姓氏字典比對是啟發式判斷，不是真正的命名實體辨識。單一姓氏字出現在句子中但不是當作姓名使用時（例如姓氏字剛好是句子開頭的其他用字），可能被誤判為姓名候選；反之複姓、字典未收錄的罕見姓氏會被漏掉。此限制會誠實寫進 README，不視為 bug。

## 6. 非功能需求

- **隱私**：所有偵測與遮蔽皆在瀏覽器端完成，內容不上傳、不送出任何網路請求（比個資遮蔽工具本身若對外連線會是最大的諷刺，需特別在 SECURITY_REVIEW.md 強調驗證此點）
- **零依賴**：regex 與字串比對皆為原生 JavaScript，不需要內嵌任何第三方函式庫（比 Day3 需要 jsdiff 更單純）
- **相容性**：Chrome／Safari／Edge 最新版正常運作；`file://` 協定下雙擊開啟需正常運作
- **效能**：單次輸入 1 萬字以內的文件，偵測與標示需在使用者可接受的時間內完成

## 7. UI/UX 需求

- 上方：文字輸入區（含拖曳提示）
- 中段：兩個並排的輸入框——「機敏字庫」（每行一個關鍵字）與「代換字庫」（每行對應機敏字庫同一行的代換詞，可留空），「開始偵測」按鈕
- 偵測結果：原文字內以不同底色標示個資／機敏字庫命中（需標示色彩圖例）
  - 個資標示旁附勾選框（預設全部勾選），對應 F6 的人工確認流程
  - 機敏字庫命中不附勾選框（F5 直接套用，畫面上偵測完成即已是套用代換／遮蔽後的結果）
- 「執行遮蔽」按鈕：只針對個資標示、只替換已勾選的項目，依規則部分遮蔽
- 底部顯示統計摘要（個資／機敏字庫命中／已遮蔽／已代換筆數）
- 提供「複製處理後文字」「下載處理後 .txt」按鈕

## 8. 技術選型

- HTML + CSS + 原生 JavaScript，無外部函式庫
- 個資偵測 regex（初版，實作時需用真實格式樣本覆核）：
  - 身分證字號：`[A-Za-z][12]\d{8}`（開頭字母不限大小寫）
  - 手機號碼：`09\d{2}-?\d{3}-?\d{3}`
  - 市話（含區碼、可選分機，分機最多 6 碼）：`\(?0\d{1,2}\)?-?\d{3,4}-?\d{4}(?:#\d{1,6})?`
  - Email：標準 email regex
  - 姓名：內建常見中文單姓字典（王、李、張、陳、林、黃、吳、劉、蔡、楊…等常見姓氏），比對「字典姓氏＋緊接 1～2 個中文字」
- 個資遮蔽規則（F3，依類型套用，取代原本統一的 `[已遮蔽]`）：
  - 身分證字號：保留第 1 碼（字母）＋末 3 碼數字，中間用 ● 遮蔽（例如 `A123456789` → `A●●●●●●789`）
  - 手機號碼／市話：留末 3 碼數字，其餘（含原本的括號、連字號）用 ● 遮蔽
  - Email：@ 前僅留第 1 碼，其餘本地端字元用 ● 遮蔽；@ 後網域維持原樣（例如 `test@example.com` → `t●●●@example.com`）
  - 姓名：保留姓氏，其餘字元換成 ○，長度比照原姓名去掉姓氏後的字數（例如 `王小明` → `王○○`，`陳大文` → `陳○○`）
- 機敏字庫比對：逐行讀取關鍵字清單，對輸入文字做 `indexOf`／字串比對，非 regex（避免使用者輸入的關鍵字含 regex 特殊字元造成非預期行為）；代換字庫依相同行號索引取得對應代換詞，該行為空或代換字庫行數不足時視為沒有代換詞，退回 `[已遮蔽]`

## 9. 驗收標準（Acceptance Criteria）

1. 貼上含身分證字號、手機號碼、市話（含分機）、Email、常見姓氏姓名各一筆的文字並執行偵測，五種類型皆需被正確標示。
2. 標示結果中取消勾選其中一筆個資，執行遮蔽後該筆內容需維持原樣、不被替換；其餘勾選項目需依對應規則正確做部分遮蔽（身分證留頭尾、手機/市話留末 3 碼、Email 留 @ 前 1 碼、姓名留姓氏換○）。
3. 機敏字庫貼上「鳳凰專案」，代換字庫對應行貼上「本專案」，文字中出現「鳳凰專案」執行偵測後，需直接被換成「本專案」，不需要勾選確認、也不需要另外點擊遮蔽按鈕。
4. 機敏字庫貼上「李永昌」，代換字庫對應行留空，文字中出現「李永昌」執行偵測後，需直接被換成 `[已遮蔽]`。
5. 拖曳 .txt 檔案到輸入區，需正確讀取檔案內容並帶入。
6. 點擊「下載處理後 .txt」需下載檔案，內容與畫面顯示的處理後文字一致（含個資遮蔽與機敏字庫代換的最終結果）。
7. 開發者工具 Network 面板確認偵測與遮蔽過程無任何對外請求。
8. 直接以 `file://` 方式雙擊開啟 HTML 檔，貼上文字並執行偵測與遮蔽需正常運作。
9. 貼上一段完全不含個資、也不含機敏字庫任何關鍵字的文字並執行偵測，統計摘要需顯示 0 筆，不誤判。

## 10. Out of Scope

- 不做地址、生日、銀行帳號、信用卡卡號的自動偵測
- 不做機敏字庫／代換字庫的語意判斷或 AI 輔助識別，僅支援使用者自訂關鍵字的精確字串比對
- 不支援批次多檔案處理
- 不直接處理 PDF／圖片，僅處理已轉出的純文字（需銜接 Day2 工具）
- 姓名偵測不做真正的命名實體辨識，僅用固定姓氏字典做啟發式比對，明確接受一定程度的誤判／漏判（見第 5 節已知限制）
