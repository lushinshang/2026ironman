# Day 8 PRD — 異動重點摘要產生器

> 交付類型：**A 類**（GitHub Pages／下載 HTML，純前端執行，零依賴、零對外請求）

---

## 1. 背景與痛點

甲方公告招標文件常常改版數次，承辦人員用 [Day7 文字差異比對器](../Day7/index.html) 可以抓出「新增／刪除／修改」的每一句差異，但 Day7 的差異報告是逐句列出的原始清單——一次改版動辄十幾二十句差異，其中多數只是格式調整、標點修正、用語微調，真正需要跟主管或同事說明的「實質重點」可能只有兩三條。

承辦人員目前得自己從落落長的差異清單裡，肉眼篩出重點、手動打字整理成一段摘要文字，才能放進簽呈或會議報告。這個「篩選＋改寫成摘要」的手工步驟，就是 Day8 要解決的問題。

## 2. 目標使用者

- 主要：已經用 Day7 產出差異報告的承辦人員，需要把差異清單濃縮成給主管看的重點摘要
- 次要：任何手上有一份「新增／刪除／修改」條列清單、想快速整理成摘要文字的使用者

## 3. 使用情境（User Story）

1. 身為剛用 Day7 比對完新舊版招標公告的承辦人員，我把 Day7 下載的差異報告 MD 貼進 Day8，就能看到一份可勾選的異動清單，不用重新讀一遍原始比對畫面。
2. 身為要跟主管報告「這次改了什麼」的承辦人員，我只勾選真正重要的幾條異動，工具就幫我組成一段可直接複製貼上的摘要文字，我還能在預覽區手動微調字句。

## 4. 功能需求（MVP，本次必須完成）

| # | 功能 | 說明 |
|---|---|---|
| F1 | 貼上差異報告 | 提供文字輸入區，貼上 Day7「下載差異報告 MD」的完整內容（`# 文字差異比對報告` 開頭、`## 差異內容` 條列 `- **修改／新增／刪除**：...` 的格式） |
| F2 | 拖曳 .md 檔案 | 支援直接拖曳 Day7 下載的 `.md` 差異報告檔案，自動讀取內容帶入輸入區 |
| F3 | 解析成異動清單 | 依 F1 格式解析出每一條異動的類型（新增／刪除／修改）與內容，解析失敗（格式不符）需明確提示，不靜默失敗 |
| F4 | 可勾選異動清單 | 逐條顯示異動，每條含類型標籤（新增／刪除／修改，色彩區分）與內容；每條前方有勾選框，預設全部勾選 |
| F5 | 全選／全不選 | 提供「全選」「全不選」按鈕，方便使用者從全選狀態開始逐條取消不重要的項目 |
| F6 | 統計摘要 | 顯示「已勾選 X 條／全部 Y 條」，並分別列出已勾選中新增／刪除／修改各幾條 |
| F7 | 摘要預覽（可編輯） | 依已勾選項目自動組成一段條列式摘要文字（見第 8 節格式），顯示在可直接編輯的文字區塊，使用者可自由增刪修改文字 |
| F8 | 複製與下載 | 一鍵複製摘要預覽區目前內容到剪貼簿；一鍵下載摘要為 `.md` 檔案 |

## 5. 非必要／可延伸功能（Nice to have，非 Day8 範圍）

- AI 自動判斷「重要性」並預先勾選建議項目（本系列堅持零後端、零外部 API 依賴，不做）
- 異動清單依關鍵字搜尋／篩選
- 多份差異報告合併比對
- 摘要文字的格式模板選擇（簽呈體、會議紀錄體等）

> 上述功能明確排除於 Day8 MVP，避免範圍膨脹；若後續有需求再開新任務。

## 6. 非功能需求

- **隱私**：所有解析與摘要組成皆在瀏覽器端完成，內容不上傳、不送出任何網路請求
- **零依賴**：純 HTML + CSS + 原生 JavaScript，不內嵌任何外部函式庫
- **相容性**：Chrome／Safari／Edge 最新版正常運作；`file://` 協定下雙擊開啟需正常運作
- **輸入容錯**：貼上內容不完全符合 Day7 格式時（例如使用者手動刪改過），仍需盡量解析可辨識的 `- **修改／新增／刪除**：...` 條列行，無法解析的行以「格式不符，略過 N 行」提示，不中斷整個流程

## 7. UI/UX 需求

```
┌─────────────────────────────────────────┐
│ Day8｜異動重點摘要產生器                    │
├─────────────────────────────────────────┤
│ 【輸入來源】                               │
│ ┌───────────────────────────────────┐   │
│ │ 貼上 Day7 差異報告 MD               │   │
│ │ （或拖曳 .md 檔案到此處）            │   │
│ └───────────────────────────────────┘   │
│              [解析異動清單]                │
├─────────────────────────────────────────┤
│ 【統計摘要】已勾選 3／12 條                  │
│ 新增 1・刪除 0・修改 2        [全選][全不選] │
├─────────────────────────────────────────┤
│ 【異動清單】                               │
│ ☑ [修改] 投標保證金由 5% 調整為 10%          │
│ ☑ [新增] 增列「須檢附廠商資本額證明」          │
│ ☐ [修改] 標點符號調整（原文）→（現文）        │
│ ☑ [刪除] 刪除「得延長截止日」但書              │
│ ...（逐條列出，可捲動）                     │
├─────────────────────────────────────────┤
│ 【摘要預覽】（可直接編輯）                   │
│ ┌───────────────────────────────────┐   │
│ │ 本次公告異動重點：                  │   │
│ │ 1. 投標保證金由 5% 調整為 10%       │   │
│ │ 2. 增列「須檢附廠商資本額證明」      │   │
│ │ 3. 刪除「得延長截止日」但書          │   │
│ └───────────────────────────────────┘   │
│            [複製摘要]  [下載摘要 MD]        │
└─────────────────────────────────────────┘
```

- 輸入來源區：文字輸入框（含拖曳提示）＋「解析異動清單」按鈕
- 統計摘要：即時反映勾選狀態變化，不用重新點擊解析
- 異動清單：類型標籤沿用 Day7 的色彩邏輯（新增／刪除／修改），逐條可勾選，清單過長時可捲動
- 摘要預覽：`<textarea>` 或 `contenteditable`，勾選狀態變化即時重新生成內容；使用者手動編輯後的內容，除非重新按「解析」或改變勾選，否則不覆蓋使用者的手動修改

## 8. 摘要文字格式

```
本次公告異動重點：
1. <修改／新增／刪除的內容摘述>
2. ...
```

- 逐條依清單勾選順序（即原始差異報告的順序）編號列出
- 「修改」項目直接採用差異報告裡的內容描述（含 `→`）；「新增」「刪除」比照差異報告原文
- 若使用者取消全部勾選，摘要預覽顯示「（無勾選項目）」

## 9. 技術選型

- HTML + CSS + 原生 JavaScript，無外部函式庫
- 解析邏輯：以正則規則比對 `- **修改**：`old` → `new``、`- **新增**：`new``、`- **刪除**：`old`` 三種行首格式，逐行解析

## 10. 驗收標準（Acceptance Criteria）

1. 貼上一份標準格式的 Day7 差異報告 MD，按「解析異動清單」後，清單條數與報告中的新增／刪除／修改總數一致。
2. 拖曳 Day7 下載的 `.md` 檔案到輸入區，需正確讀取檔案內容並自動帶入。
3. 取消勾選其中幾條後，統計摘要與摘要預覽需立即同步更新，不用重新按解析按鈕。
4. 「全選」「全不選」按鈕需正確改變所有項目的勾選狀態，並同步更新統計與預覽。
5. 手動編輯摘要預覽區文字後，只要沒有改變勾選狀態或重新解析，編輯內容需保留不被覆蓋。
6. 點擊「下載摘要 MD」需下載檔案，內容與摘要預覽區目前顯示文字一致。
7. 貼上格式不符的內容（例如空白或跟 Day7 格式完全不同的文字），需顯示明確提示，不得白畫面或拋出例外。
8. 開發者工具 Network 面板確認全程無任何對外請求。
9. 直接以 `file://` 方式雙擊開啟 HTML 檔，貼上內容並解析需正常運作。

## 11. Out of Scope

- 不做 AI 自動摘要或重要性判斷
- 不支援多份差異報告合併處理
- 不做摘要格式模板選擇（僅提供第 8 節單一格式）
- 不解析 Day7 以外來源的差異報告格式（如手動拼湊的清單需自行整理成第 4 節解析規則能辨識的格式）
