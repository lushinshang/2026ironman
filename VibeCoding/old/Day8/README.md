## 🧠 3. AI 思考與自言自語紀錄 (Vibe Coding 日誌)

### 本日 Debug 與架構思考歷程：
1. **遇到的問題**：
   * PRD 對「格式不符，略過 N 行」沒有給精確定義：貼上的內容裡，標題列與統計摘要列（如「- 新增：2 句」）本身也是 `-` 開頭，如果無腦套用「三種正則比對不到就算略過」的規則，會把這些正常結構性內容也算成「略過」，變成誤導訊息。
   * 摘要預覽是可編輯的 `<textarea>`，但清單勾選狀態一變動就要重新生成內容——兩者衝突時（使用者手動改了字，之後又動了勾選框）該聽誰的？
2. **AI 的思考與解決路徑**：
   * 只把「看起來像條列格式（`- **...**`）但三種正則都比對不到」的行計入「略過 N 行」，標題／統計列排除在外，讓完全不符格式的輸入（如純英文亂碼）落入「未偵測到可辨識異動內容」的明確失敗提示，而不是顯示一個誤導性的「略過 0 行」。
   * 摘要預覽只在「解析」「勾選狀態變動」兩個事件時重新生成覆蓋；使用者手動編輯後、沒有再觸發這兩者之一，內容就保留不覆蓋——這樣「先勾選再手動微調文字」的實際使用順序不會被打斷。
3. **最終解法與結論**：
   * 依 `sdd/day8-change-summary/` 走完 SDD 提案→實作→驗收：先派一個 general-purpose subagent 讀 PRD＋Day7 版面風格＋Day7 的 `buildMarkdownReport()` 實際輸出格式後動手實作（T1～T8），完成後另派一支完全獨立、沒看過實作過程的 fresh agent 只憑 PRD 與驗收條件重新實測 12 項條件（含拖曳讀檔、剪貼簿複製、下載內容比對、`file://` 協定），全數 PASS。

## 💻 4. 本日程式實作片段

```javascript
// 解析 Day7 差異報告 MD 格式（Day8/index.html）
function parseDiffReport(text){
  var lines = text.split(/\r?\n/);
  var items = [];
  var skipped = 0;
  lines.forEach(function(line){
    var trimmed = line.trim();
    if (!trimmed.startsWith('- ')) return; // 非條列行，略過不計數
    var modified = trimmed.match(/^- \*\*修改\*\*：`(.*)` → `(.*)`$/);
    var added = trimmed.match(/^- \*\*新增\*\*：`(.*)`$/);
    var removed = trimmed.match(/^- \*\*刪除\*\*：`(.*)`$/);
    if (modified) items.push({ type: 'modified', oldText: modified[1], newText: modified[2] });
    else if (added) items.push({ type: 'added', newText: added[1] });
    else if (removed) items.push({ type: 'removed', oldText: removed[1] });
    else if (/^- \*\*/.test(trimmed)) skipped++; // 像條列但比對不到，才算略過
  });
  return { items: items, skipped: skipped };
}
```
