Day 2 PRD — PDF 轉 TXT/MD

交付類型：A 類（GitHub Pages／下載 HTML，純前端執行，唯一例外是需內嵌 pdf.js 函式庫解析 PDF，但不上傳任何內容到伺服器）

1. 背景與痛點

主情境：合約／公文改版比對（銜接 Day3 文字差異比對器）

承辦人員收到廠商／對方寄來的合約、公文修訂版，檔案是 PDF 而不是 Word，無法直接複製貼上做逐字修改或比對；就算硬複製，因為排版、表格、跨欄或浮水印的關係，貼出來的文字常常斷行斷得亂七八糟、空格黏在一起，還得手動清理才能真正拿去用（例如貼進 Day3 的差異比對器）。

延伸情境：研究者／學生用 AI 協助讀論文

AI 興起後要讀的論文、報告數量暴增，很多人會直接把 PDF 丟給 AI 助理做摘要、解讀。但 PDF 是版面格式（含座標、字型、圖層等資訊），AI 解析同一份內容時消耗的 token 遠高於純文字，且容易把版面雜訊（分欄錯位、頁碼、浮水印）當內容一起塞進 context，稀釋重點、增加幻覺風險。先轉成乾淨的 TXT/MD 再餵給 AI，是更正統的做法。

2. 目標使用者

  • 主要：一般辦公室行政人員、承辦人員，不具備程式背景
  • 次要：需要用 AI 協助分析文獻的研究者、學生

3. 使用情境（User Story）

  1. 身為要比對合約修訂版的承辦人員，我把 PDF 合約拖進這個工具，就能拿到一份乾淨的純文字或 Markdown，直接貼去比對兩個版本改了哪裡，不用先開 Word／Acrobat 轉檔。
  2. 身為要用 AI 協助分析論文的研究者，我把 PDF 論文轉成乾淨的 TXT/MD，再貼給 AI 助理處理，用更少的 token 換到更準確的解讀結果，同時把這份 MD 存成自己的筆記。

4. 功能需求（MVP，本次必須完成）

# 功能 說明
F1 PDF 上傳／拖曳 支援點擊選檔或拖曳 PDF 檔案進入頁面
F2 文字擷取 用 pdf.js 讀取 PDF 文字層，依閱讀順序（頁面內由上到下、由左到右）輸出全文
F3 無文字層偵測 若 PDF 完全沒有文字層（掃描件／圖片 PDF），明確顯示錯誤提示，不得空白或當機
F4 圖片忽略 PDF 內的圖片不處理、不加 placeholder，直接跳過
F5 表格不重建結構 不嘗試依座標重建表格欄位，依 pdf.js 預設閱讀順序原樣輸出；UI 需提示「表格內容可能跑版，請人工核對」
F6 浮水印過濾 偵測「同一字串於 ≥ 80% 頁面重複出現，且文字旋轉角度不為 0」的文字物件，判定為浮水印並從輸出中排除
F7 輸出格式切換 提供 TXT（純文字）與 Markdown 兩種輸出檢視，可切換
F8 複製到剪貼簿 一鍵複製目前輸出格式的全文內容
F9 下載檔案 一鍵下載 .txt 或 .md 檔案，內容與畫面顯示一致
F10 轉換進度提示 頁數較多、檔案較大時顯示處理中狀態，避免使用者以為當機

5. 非必要／可延伸功能（Nice to have，非 Day2 範圍）

  • 下載本工具離線版（比照 Day1 F13；因需內嵌 pdf.js，檔案會明顯變大，先不做）
  • 批次多檔案轉換
  • 表格結構重建（依座標推欄位）
  • 非旋轉／半透明浮水印過濾
  • OCR（掃描版 PDF 文字辨識）

上述功能明確排除於 Day2 MVP，避免範圍膨脹；若後續有需求再開新任務。

6. 非功能需求

  • 隱私：所有 PDF 解析與文字處理皆在瀏覽器端完成，檔案內容不上傳、不送出任何網路請求。
  • 零依賴的例外：本工具需內嵌 pdf.js 函式庫才能解析 PDF，是本系列少數不追求「極輕量單檔」的例外，需在 README／文章中說明取捨原因。
  • 相容性：Chrome／Safari／Edge 最新版正常運作；file:// 協定下雙擊開啟需正常運作（pdf.js 的 worker 載入方式需特別驗證是否受 file:// 限制）。
  • 效能：50 頁內的一般文件轉換需在使用者可接受的時間內完成（顯示處理中狀態，避免誤以為當機）。

7. UI/UX 需求

  • 上方或左側：PDF 上傳／拖曳區
  • 轉換完成後：TXT／Markdown 切換 tab，顯示轉出內容（唯讀）
  • 提供「複製」「下載 TXT」「下載 MD」按鈕
  • 表格跑版風險提示、浮水印已過濾的提示（讓使用者知道工具動過手腳，內容可能與原文有出入）
  • 偵測到無文字層 PDF 時的明確錯誤訊息

8. 技術選型

  • HTML + CSS + 原生 JavaScript + 內嵌 pdf.js（Mozilla 官方函式庫，瀏覽器端解析 PDF）
  • 浮水印判定：依 pdf.js getTextContent() 回傳的 transform 矩陣計算旋轉角度，非 0 度視為候選，再比對跨頁重複比例

9. 驗收標準（Acceptance Criteria）

  1. 上傳一份多頁、含文字層的一般 PDF，轉出文字內容需與原文人工核對一致。
  2. 上傳一份含旋轉浮水印文字（跨頁重複）的 PDF，轉出結果不應包含該浮水印文字。
  3. 上傳一份含表格的 PDF，轉出結果即使跑版也不可讓程式當機或漏字漏頁。
  4. 上傳一份無文字層（掃描版／圖片）的 PDF，需顯示明確錯誤提示。
  5. 點擊「下載 TXT」「下載 MD」需各自下載檔案，內容與畫面顯示一致。
  6. 開發者工具 Network 面板確認轉換過程無任何對外請求。
  7. 直接以 file:// 方式雙擊開啟 HTML 檔，上傳 PDF 並轉換需正常運作。

10. Out of Scope

  • 不做圖片內容辨識或 OCR
  • 不做表格結構重建（欄位／儲存格）
  • 不處理跨頁表格合併
  • 不處理非旋轉、純半透明的浮水印
  • 不支援批次多檔案一次轉換
  • 不做雲端同步或帳號系統
