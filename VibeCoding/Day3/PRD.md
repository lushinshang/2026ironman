# Day 3 PRD — 繁簡與在地化轉換器

> 交付類型：**A 類**（GitHub Pages／下載 HTML，純前端執行，零外部函式庫依賴；詞典資料內嵌於檔案內，執行時不連網）

> 📌 **題目併入說明**：本工具同時涵蓋 100 題清單 **#11 繁簡轉換器** 與 **#12 台灣用語轉換器** 兩題的功能，#11 自本次起標記為「已併入 Day3，不再獨立開發」。

---

## 1. 背景與痛點

### 主情境：承接 Day2 的「發布前最後一道語言校對」

依 Day1-5「個人寫作發布流程」的管線關係，Day3 夾在 Day2（贅詞與 AI 味檢查）與 Day4（Markdown 轉 HTML）之間：Day2 處理「文字品質」（贅詞、AI 腔），Day3 處理「用字用語的地區慣用差異」，處理完的文字要能直接貼進 Day4 發布，不該再回頭改用字。

會遇到這個問題的兩種輸入來源：

1. **引用／轉載大陸來源內容**：貼上的文字本身就是簡體字，且用語（視頻、軟件、優化）也是大陸慣用語，兩個問題同時存在。
2. **AI 翻譯英文產生的中文**：使用頻率通常比第一種更高。輸出雖然已經是繁體字，但因為多數翻譯模型的中文語料偏大陸來源，用語仍常帶「視頻」「軟件」這類詞——這種情況沒有簡體字問題，只有用語問題。

兩種來源共用同一套處理邏輯，差別只在「要不要跑簡轉繁」這一步。

### 延伸情境

- 跨海峽協作文件（陸資公司台灣分部、兩岸團隊合作）定稿前的用語校對。
- 逐字稿／字幕潤飾，轉錄大陸來源影片內容後貼上處理。

## 2. 目標使用者

- 主要：部落格／技術文章作者，需要引用大陸來源內容或校對 AI 翻譯結果的人
- 次要：跨海峽協作文件校對者、逐字稿潤飾使用者

## 3. 使用情境（User Story）

1. 身為要引用大陸技術文章的使用者，我把原文貼進來，系統先做簡體轉繁體（詞組級消歧義，正確處理「发」「后」「干」這類一對多的簡體字），再把科技類、生活類的大陸用語換成台灣用語，Markdown 語法（code block、連結）不受影響，得到可以直接貼進 Day4 發布的文字。
2. 身為用 AI 翻譯英文的使用者，我貼上翻譯後的中文（已經是繁體，沒有簡體字），系統只需要偵測並替換其中的大陸用語；遇到網路流行語（內卷、躺平）這類沒有台灣對應詞的詞彙，只標記提示、不強制替換，我自己決定要不要改寫。
3. 身為想自訂詞庫的使用者，我可以在畫面上編輯／新增各分類詞庫（簡繁詞組、科技用語、生活用語、網路流行語），也可以個別開關某一類是否要處理，並匯出／匯入 JSON 備份。

## 4. 功能需求（MVP，本次必須完成）

| # | 功能 | 說明 |
|---|---|---|
| F1 | 文字輸入 | 單一文字輸入區，支援直接貼上，也支援拖曳 .txt/.md 檔案自動帶入內容（沿用既有拖曳邏輯） |
| F2 | 簡體轉繁體 | 內嵌 OpenCC 開源詞組級詞典（見第 8 節技術選型），最長詞組優先比對消歧義，未命中詞組的單字回退到單字對照表；可獨立開關 |
| F3 | 高信心用語替換（科技類／生活類） | 兩個分類詞庫（科技用語：視頻→影片、軟件→軟體；生活用語：番茄＝西紅柿、鳳梨＝菠蘿），命中後直接替換，不需勾選確認；兩類可分別開關 |
| F4 | 低信心用語標記（網路流行語） | 獨立詞庫（內卷、躺平、破防、666），命中後僅標記提示「這是大陸網路用語，讀者可能看不懂」，不自動替換、不提供一鍵替換 |
| F5 | Markdown 語法保護 | 行內反引號 `` `code` ``、code block（三個反引號區塊）、連結語法 `[text](url)` 的 `url` 部分內容不列入 F2／F3／F4 的處理範圍 |
| F6 | 詞庫可編輯＋匯入匯出 | 四個詞庫（簡繁詞組、科技用語、生活用語、網路流行語）皆可在畫面上編輯，並可各自匯出／匯入 JSON |
| F7 | 統計摘要 | 顯示「簡轉繁 N 字／科技用語替換 N 筆／生活用語替換 N 筆／網路流行語提示 N 筆」 |
| F8 | 複製與下載 | 一鍵複製處理後文字；一鍵下載處理後的 .txt 檔案 |

## 5. 非必要／可延伸功能（Nice to have，非 Day3 範圍）

- 句式／量詞層次的轉換（「一輛車」vs「一台車」）：純規則無法判斷語境是否自然，強做容易誤判，本次不做
- 翻譯腔固定套語偵測（「當…的時候」「在…方面」這類英文直譯句型）：使用者確認本次先不做，AI 翻譯英文只當作「用語替換」的一種輸入情境處理，不額外開發翻譯腔偵測機制
- 雙向轉換（台灣用語→大陸用語）：主線是台灣讀者發布內容，先不做反向
- 香港／新加坡等其他中文變體詞庫：先聚焦「大陸→台灣」，其他變體不在範圍
- 全篇語意或翻譯品質評分：不做

**已知限制**：簡體歧義字消歧義完全依賴內嵌詞組詞典的覆蓋率，未收錄的詞組仍可能轉錯；網路流行語詞庫需要持續更新，新造詞跟不上是正常現象，不視為 bug。此限制會誠實寫進 README。

## 6. 非功能需求

- **隱私**：所有轉換皆在瀏覽器端完成，內容不上傳、不送出任何網路請求
- **零依賴**：詞典資料以純資料形式內嵌於 HTML 檔案內，不即時呼叫任何外部 API（含 OpenCC 官方服務），執行時零連網
- **授權**：內嵌的 OpenCC 詞典資料為開源授權（Apache License 2.0），需在 README／原始碼註解標明資料來源與授權
- **相容性**：Chrome／Safari／Edge 最新版正常運作；`file://` 協定下雙擊開啟需正常運作
- **效能**：單次輸入 1 萬字以內的文件，轉換需在使用者可接受的時間內完成

## 7. UI/UX 需求

- 上方：文字輸入區（含拖曳提示）
- 詞庫設定區（可摺疊，預設收合）：四個詞庫編輯區（簡繁詞組／科技用語／生活用語／網路流行語），各自匯入匯出按鈕；簡繁詞組、科技用語、生活用語旁各有開關（預設開啟），網路流行語只做提示不提供「關閉」以外的行為
- 「開始轉換」按鈕
- 偵測結果：原文以不同底色標示（簡轉繁／科技用語／生活用語為已直接替換的結果，網路流行語為標記提示，需附色彩圖例）
- 底部顯示統計摘要
- 提供「複製處理後文字」「下載處理後 .txt」按鈕

## 8. 技術選型

- HTML + CSS + 原生 JavaScript，無外部函式庫載入（詞典資料以內嵌 JS 物件形式存在，非執行期網路請求）
- **簡繁轉換**：內嵌 OpenCC（Apache License 2.0）的詞組級對照表資料（如 `STPhrases`／`TWPhrasesIT`／`TWVariants` 等），實作時需確認實際資料檔案大小、篩選出必要子集以控制單檔體積，比對邏輯採最長詞組優先（Maximum Matching），未命中詞組時回退到單字對照表
- **用語替換詞庫格式**：比照 Day2／Day9 的做法，每行 `詞彙,分類`，精確字串比對（非 regex）
- **Markdown 語法保護**：正則抓取 `` `[^`]*` ``（行內反引號）、` ```[\s\S]*?``` `（code block）、`\[[^\]]*\]\([^)]*\)`（連結，僅保護 `()` 內的 URL 部分）範圍，比對迴圈時跳過
- **重疊解析**：比照 Day2 F2 的做法，所有命中依起點排序、同起點取最長者，避免詞組互相重疊時重複計算

## 9. 驗收標準（Acceptance Criteria）

1. 貼上含常見一對多歧義字（如「头发」「以后」「干净」）的簡體文字，執行轉換後需正確轉成對應繁體（「頭髮」「以後」「乾淨」），而非單字表逐字誤轉。
2. 貼上含科技類與生活類大陸用語各一筆的文字，執行轉換後兩者皆需直接被替換成台灣用語，不需勾選確認。
3. 貼上含網路流行語（如「內卷」）的文字，執行轉換後該詞需被標記提示，但原文字不被替換掉。
4. 貼上含 Markdown 語法（`` `软件` ``、code block、`[链接](软件.com)`）的文字，執行轉換後這些語法範圍內的內容不應被簡繁轉換或用語替換動到。
5. 關閉「生活用語」開關後執行轉換，生活用語不應被替換，科技用語與簡繁轉換仍正常運作。
6. 在詞庫編輯區新增自訂用語詞彙後執行轉換，該詞需被正確替換；匯出詞庫 JSON 後清空再匯入，需完整還原。
7. 拖曳 .txt 檔案到輸入區，需正確讀取檔案內容並帶入。
8. 點擊「下載處理後 .txt」需下載檔案，內容與畫面顯示的轉換後文字一致。
9. 開發者工具 Network 面板確認轉換過程無任何對外請求。
10. 直接以 `file://` 方式雙擊開啟 HTML 檔，貼上文字並執行轉換需正常運作。
11. 貼上一段純繁體、不含任何大陸用語與網路流行語的文字，執行轉換後文字應維持不變，統計摘要顯示 0 筆。

## 10. Out of Scope

- 不做句式／量詞層次的自然度判斷或改寫
- 不做翻譯腔固定套語偵測
- 不做雙向轉換（台灣→大陸）
- 不支援香港／新加坡等其他中文變體
- 不做全篇語意或翻譯品質評分
